# Explain it: what each app module does

One line per module, copied from the comment at the top of each file.

| Module | What it does |
|---|---|
| `src/main.js` | Boots DuneSight: creates the globe, loads the site index, mounts the UI (src/ui/ui.js) with each site's data, runs the fly-in, builds each site's layers on first visit and wires the UI's callbacks to layers, timeline, picking, camera and the dossier. |
| `src/ui/ui.js` | DuneSight UI: header, panels (speed, wind, reached places, selection), timeline, legend, first-visit guide, mobile sheet, credits footer. Also exports `MAP_STYLE`, the line colours and widths the map layers use. |
| `src/ui/site-data.js` | Builds the data object the redesigned UI (ui.js) renders, for one site, from that site's published files only (no site ids, no sample numbers). |
| `src/ui/tokens.css` | Design tokens of the "field survey instrument" look: colours (each carries one meaning), type, spacing. |
| `src/ui/ui.css` | Panels, header, timeline, legend, guide and mobile sheet, scoped under `.ds-ui`, plus the pieces the app added (reached list, selection card, measured/projected tags, phone footer). |
| `src/basemap.js` | Creates the Cesium viewer: ion terrain + imagery when a token works, otherwise Esri imagery on a flat globe, and a dark globe with a note when the basemap is offline. |
| `src/data.js` | Fetches and caches the static site data under public/data/ (base-path aware) and derives a few values the HUD needs. |
| `src/state.js` | App state (site, mode, timeline position, selection, toggles) plus a tiny event emitter that modules subscribe to. |
| `src/format.js` | Number, unit, range, compass-point, date and year formatting in one place, so nothing prints "null", "undefined" or "NaN". |
| `src/geo.js` | Small geodesy helpers: metre offsets on the ground around a lon/lat, polygon rings, centroids and point-in-polygon. |
| `src/timeline.js` | Timeline model: the stops for a site (every observed scene and display-only image in year order, then every year to 2050) with the frames to draw at each; the bar and its controls are drawn by the UI (src/ui/ui.js). |
| `src/layers/frames.js` | Imagery-frame layer: drapes the manifest's observed Landsat frames (display-only Landsat 7 frames with their scan-line gaps painted as a neutral no-data hatch) and stone-tinted projected frames (the projected colour) on the globe inside the exact frame bounds, with cross-fades and an optional changed-pixel overlay. |
| `src/layers/vectors.js` | Motion-vector layer: one ground-clamped arrow per detected 480 m window, pointing along heading_deg, in the measured-blue accent (fainter = weaker match) with a dark casing, length on a stated time scale, plus true-scale displacement tracks in projected years (stone, the projected colour). |
| `src/layers/targets.js` | Target layer: road segments, farms and built-up areas from targets.geojson, batched into a few ground primitives, styled per threat status like the legend (dark casing, the "possible" class dashed), coloured by the timeline year and shown or hidden per status class. |
| `src/layers/dunes.js` | Large-dune layer: NASADEM-resolved dune outlines (Nov 2025 positions) styled by class like the legend (colour, width, dark casing) with id labels (decluttered on screen), threat pulse, and the Feb 2000 outlines dotted for then-vs-now. |
| `src/layers/util.js` | Shared helpers for the batched ground primitives: colour and show attributes, readiness, line/polygon instances, dash patterns and the map colours (from the UI's MAP_STYLE, so map and legend match). |
| `src/hud/card.js` | Info cards for a picked dune, target or motion arrow: every number with units and its range where the data gives one, plus the data source. |
| `src/hud/dossier.js` | "How we know" dossier for the current site, composed from the data files: method, datasets with links/DOIs, data handling, uncertainty, validation, threat definition, limits and repo links. |
| `src/hud/credits.js` | Credits: the exact grant line and the NASA / not-NASA split of sources.json (the footer itself is drawn by the UI in src/ui/ui.js). |
| `src/style.css` | DuneSight app styles outside the panel UI (src/ui/ui.css): page and globe, Cesium credits, toasts, boot screen, the "How we know" dossier, and selection-card contents. |
| `tests/e2e/acceptance.spec.js` | Acceptance tests from docs/build-spec.md section 8 (the automatable ones) plus the redesigned-UI checks, run against the real data files. |
| `tests/e2e/helpers.js` | Shared e2e helpers: read the real data files, boot the app and wait for a site, collect console errors. |
| `tests/tools/screens.mjs` | Dev helper: retakes the screenshots in docs/screenshots/ from a running server, one scripted view each. |
| `playwright.config.js` | Playwright e2e config: dev server or production build under /dunesight/, plus a token-less dev server for the fallback test. |

## Design choices the spec left open

- **One look.** The interface is the user-supplied "field survey instrument" design (`src/ui/`): warm charcoal panels, IBM Plex Sans, one plain-English sentence leading each panel. Its colour rule holds on the map too: blue means measured motion, stone (with a dashed edge or hatch) means projected, the warm ramp means threat to a road, farm or built-up area, the cool ramp means dune class. Every map line has a dark casing underneath so it reads over bright sand, and its colour, width and dash are the legend sample's (`MAP_STYLE`).
- **Arrow scale.** Arrow length is a stated time scale: ×1 = 100 years of motion at the measured speed (1 m/yr → 100 m). Each site opens at the largest of ×1/×2/×4 at which a 90th-percentile arrow is no longer than the 240 m spacing between arrows (×2 at Seih Al Hama, ×1 at Sweihan and Liwa), so arrows do not run into their neighbours; the legend always prints the scale in use, and ×1/×2/×4 can be chosen there. Arrows start at the window centre (tail = where it was measured). Speed is shown by length and in the card, not by colour: all arrows are the measured blue, fainter where the match is weaker.
- **One heading per site.** The heading shown everywhere (speed panel, compass, wind sentence) is the pipeline's field median of the windows with detected motion, which `summary.json` states in `wind_agreement_note` (and `station_wind.json` repeats as `dune_heading_deg`). The vector mean of the thinned arrows drawn on the map is a different average of the same field; it appears only in the wind panel's details and the dossier, labelled as such.
- **Wind sentence.** The wind panel's lead is written from the data: within 20° the wind and dunes "move the same way", 20–45° they are "close, but not the same", beyond that the dunes "are moving" elsewhere. 20° is the heading tolerance of the cross-check rule in `summary.confirmation`.
- **Timeline stops.** Every observed frame, every display-only image, then every year from the latest scene to 2050 (so a target's reach year can be shown exactly). Between projected frames the most recent projected frame stays on screen and the readout says which frame it is; 2026–2029 show the latest observed image and say so. Every year with no frame at all is drawn as a gap (a gap of three or more years is labelled "no scenes …", shorter ones dashed), and a label under the early years names every empty year, computed from the manifest.
- **Image-only years (2003–2012).** Landsat 7 images taken after its scan line corrector failed on 31 May 2003 (`observed_display_only` in the manifest, `use` = `display_only`). They are pictures only, not used for any measurement, and look different from both measured and projected years: an open square tick and a dotted track (measured = solid blue, projected = stone hatch), an IMAGE ONLY tag in the header chip, the readout and on the map, and a dotted chip border. The readout gives the date, sensor, pixel size, scene id and the share of the box with no data. The stripes with no data are painted as a neutral dark hatch (the legend shows the same hatch), so neither dark sand nor the basemap's modern imagery shows through them. The motion arrows and the dune outlines are hidden in these years because they describe 2013–2025; the dated Feb 2000 outlines (then vs now) can still be switched on. Targets keep their colouring by year.
- **Projected imagery.** Projected frames are tinted stone over the latest observed scene (55 % at 2030 falling to 30 % at 2050), the study-area edge turns dashed stone, and a PROJECTED tag sits on the map at the box corner. The fast case can be drawn faint on top (timeline settings).
- **Target colouring.** A target with a reach year is faint in its status colour before that year and bright (pulsing) from it on, under the fast-case rule (`hit_year_min`) or the median rule (`hit_year_med`), chosen in timeline settings. "Sand at edge now" targets are bright from the latest observed frame on. "Possible within direction uncertainty" has no year and is drawn dashed. Each of the five classes has its own legend checkbox in Threat mode.
- **Reach ray.** A selected target shows the reach ray from the migrating sand edge to the footprint (stone, since it is a projection), with a faint dashed link to the 480 m window whose motion was used.
- **Changed pixels.** An optional overlay marks pixels of the median projection that differ from the latest observed frame by more than 10 grey levels (the manifest's own change statistic), keeping only pixels with at least three such neighbours so JPEG noise in the observed frame is not shown as change. They are stone with a dark edge.
- **Optional station file.** `station_wind.json` is requested only when the site's data refers to it (listed in `sites.json` files, or mentioned in `summary.json`/`wind_summary.json`), so a missing file never logs a 404. Where it is published (Seih Al Hama) the compass shows the station drift as a dashed arrow, the wind panel says in one line where the station puts the push, its details give distance, record and the station's own DP class, and the dossier has a "Ground-station wind check" section with the station's limits. MERRA-2 stays the main wind figure.
- **Cross-check lines.** In the speed panel, two rows say whether speed and heading are confirmed, partly confirmed or not confirmed by an independent check, driven only by `summary.confirmation` (no site ids in the code); the link under them opens the dossier table with every check's numbers.
- **Reached places.** In Threat mode the right-hand column shows the ranked list of reached roads, farms and built-up areas (earliest fast-case year, then smallest gap) in place of the wind panel; selecting one flies there and opens its card.
- **Selection card.** On a desktop the card opens as its own column next to the right-hand panels; on a phone it is a "Selected" tab of the bottom sheet.
- **Dossier opening.** The panel text is imported at build time from `docs/how-we-know.md` (between `<!-- panel:start -->` and `<!-- panel:end -->`), so the doc and the app say the same thing. The dossier also reopens the first-visit guide.
- **Dune labels.** After each camera move the labels are placed in screen space by priority (threatened, then taller dunes); a label that would overlap one already placed is hidden until the view is close enough.
- **Fonts.** IBM Plex Sans and Mono are bundled (`@fontsource`, SIL OFL 1.1) and loaded before the first site is drawn, so canvas labels use them and the app makes no third-party font request.
